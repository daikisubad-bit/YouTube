# 2. 企画

> 詳細な思考体系は `knowhow_master.md` 第4章（企画の考え方）・第5章（ターゲット・視聴者設計）を参照。

リサーチで見つけたネタ候補を、実際に自分のチャンネルで作る1本の動画に落とし込む工程。単なる単語の置き換えではなく、
「成功具体 → 反応した本質（なぜ刺さったか） → 自社の具体」という順で再構成する（`knowhow_master.md` 4-4）。

## 企画採用の判断（7条件・35点、`knowhow_master.md` 4-5）

企画を採用するかどうか迷ったら、各5点で採点する：①反応根拠 ②視聴者適合 ③独自中身 ④証拠保有 ⑤商品接続
⑥時間適合 ⑦戦略リスク。目安は28点以上＝優先制作、22〜27点＝不足を埋めて制作、16〜21点＝保留、15点以下＝原則ボツ。

## 企画を固めるときに確認すること

1. **切り口** — 同じネタでも「何の視点から話すか」で差が出る（初心者向け／実体験ベース／データ分析／逆張り 等）。
2. **チャンネル基盤との整合性** — `01_foundation.md` で固めたターゲット・立ち位置と矛盾しないか。
3. **差別化ポイント（工程4）を同時に検討する** — 企画を決める瞬間に「これは他の動画と何が違うのか」を1文で言えるかを
   チェックする。言えないなら企画としてまだ弱い可能性が高い。詳細は `05_differentiation.md`。
4. **台本にできる十分な情報量があるか** — 企画倒れ（タイトルは魅力的だが中身が薄い）を避けるため、この時点で
   本編に入れられる具体的な論点・エピソードが2〜3個以上あるかを確認する。

## 出し方

- 企画案は1個に絞らず2〜3案出し、それぞれ「刺さるターゲット」「根拠（リサーチのどの数字/傾向を踏まえているか）」を添える。
- ユーザーの直感（「これは違う気がする」）と食い違ったら、根拠のデータを再確認してから結論を出す。ユーザーの現場感覚は
  正しいことが多い。

## 次への引き渡し

企画が決まったら、`templates/video_project_template.md` の該当動画の進行ファイルに「決定した企画」「切り口」「差別化ポイント」を
記録し、タイトル・サムネ工程に進む。
