# 3. タイトル・サムネ

> 詳細な思考体系は `knowhow_master.md` 第6章（タイトル・サムネの考え方）・第11章（証拠と信頼）を参照。

企画と差別化ポイントを、クリックされる形に変換する工程。作って終わりにせず、可能な場合は客観評価まで行う。

## サムネから先に作る（`knowhow_master.md` 6-1）

内容を先に固めてからサムネを作ると、訴求とのズレ（釣り）が生まれやすい。正しい順序は、①このサムネの訴求で取りに行く
と先に決める→②その訴求を回収できるように台本を設計する→③台本の中で自分でツッコんで自分で回収する。強い訴求ほど、
「大げさに聞こえますよね、でも実際は…」のように台本内で誠実に回収する設計にする。

## タイトル

- 検索されるための要素（キーワード）と、クリックを誘発する要素（訴求・好奇心）のバランスを取る。キーワードだけだと
  クリック率が伸びず、訴求だけだと検索に乗らない。
- 断定的な数字訴求（「誰でも月◯万」等）は規約リスクと信頼低下につながるため避ける。数字を使うなら実績・権威付け程度に留める。
- 案は複数（3〜5案）出し、それぞれ「刺さる層」「弱点」を添える。

## サムネ

- **感情の一撃を1つに絞る** — 欲張って複数の訴求を詰めると、パッと見の解像度が落ちる。
- **文字は短く・大きく** — スマホの小さい画面でも一瞬で読める分量に絞る。
- **サムネの主張と動画の中身を一致させる** — クリック狙いで盛った内容は視聴後の期待値ズレを生み、視聴維持率を落とす。
- **「見た目は同じなのに結果/意味が違う」構造は強い** — 単純な「良い状態 vs 悪い状態」の対比は視聴者にとって驚きが少なく
  弱くなりがち。企画・台本の中に「一見同じに見えるが実は違う」というポイント（誤解されやすいパターン、意外な逆転等）が
  あれば、そこをサムネの核にできないか検討する。ただし本当にそういう要素が企画にある場合のみ使う。

## vidIQツールでの検証

| やりたいこと | ツール |
|---|---|
| タイトル案を生成する | `vidiq_generate_titles` |
| タイトル案を客観評価する | `vidiq_score_title` |
| サムネ案を生成する | `vidiq_generate_thumbnail` |
| 既存サムネを修正する | `vidiq_refine_thumbnail` |
| サムネ案を客観評価する | `vidiq_score_thumbnail` |
| 似ているサムネ（競合の型）を探す | `vidiq_similar_thumbnails` |

案を出したら、可能な場合は `vidiq_score_title` / `vidiq_score_thumbnail` で評価し、感覚だけで決めずに数字とセットで
本命を提案する。

## `00_my_knowhow.md` との関係
