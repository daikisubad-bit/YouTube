# YouTube動画制作ツール

ユーザー（daiki）が自分のチャンネルの動画を作るための、一気通貫の制作パイプライン。単発の一般論アドバイスではなく、`references/`
にある**ユーザー自身のノウハウ**と、vidIQ MCPツールで取得した**実データ**の両方を根拠にして、各工程の具体案を出す。

## 0. 最初にやること：ノウハウの有無を確認する

**`references/00_my_knowhow.md` を毎回最初に読むこと。** ここがこのツールの心臓部で、ユーザー本人の判断基準（どういうチャンネルか、
何を大事にしているか、過去の成功/失敗パターンなど）が蓄積されていく場所。

- 該当工程のノウハウが書かれていれば、それを最優先の判断基準として使う。汎用フレームワーク（`01_foundation.md` 以降の各ファイル）は
  ノウハウが薄い部分を補うための土台として使う。
- 該当工程がまだ空欄／TODOのままなら、一般論だけで進めずに、その場で必要な判断基準をユーザーに1〜2個だけ質問する（根掘り葉掘り聞きすぎない）。
  聞いた内容は会話の中で使うだけでなく、**`00_my_knowhow.md` の該当セクションに追記して**、次回以降は聞き直さずに済むようにする。
- こうして使うたびに `00_my_knowhow.md` が育っていく設計。ユーザーがまとまった資料やテキストを渡してきたときも、該当セクションに
  整理して追記する。

## 1. 全体フロー

```
0. チャンネル基盤（最初に1回。以後は土台として参照するだけ）
     ↓
1. リサーチ・ネタ出し   → references/02_research.md
     ↓
2. 企画                → references/03_planning.md
     ↓
3. タイトル・サムネ     → references/04_title_thumbnail.md
     ↓
4. 差別化ポイント       → references/05_differentiation.md
     ↓
5. 台本                → references/06_script.md
     ↓
6. 公開後フィードバック → references/07_feedback_loop.md（動画公開後、結果が出たら実施）
```

| 工程 | いつ使うか | 参照ファイル |
|------|-----------|-------------|
| 0. チャンネル基盤 | チャンネル・ペルソナ・世界観がまだ言語化されていないとき、または前提を確認したいとき | `references/01_foundation.md` |
| 1. リサーチ | ネタが欲しい、競合を調べたい、トレンドを知りたい | `references/02_research.md` |
| 2. 企画 | リサーチ結果から動画の切り口・構成を決めたい | `references/03_planning.md` |
| 3. タイトル・サムネ | タイトル案、サムネの文言・構図案が欲しい | `references/04_title_thumbnail.md` |
| 4. 差別化ポイント | 似た動画との違いを言語化したい | `references/05_differentiation.md` |
| 5. 台本 | 台本を書く／直したい | `references/06_script.md` |
| 6. 公開後フィードバック | 動画を公開して数字が出た後、次に活かしたい | `references/07_feedback_loop.md` |

工程4（差別化ポイント）は独立ステップだが、実務上は工程2（企画）を決める瞬間に同時決着することが多い。企画を詰めるときは
`05_differentiation.md` のチェックも一緒に見ること。

## 2. 動画ごとの進行管理

1本の動画ごとに `templates/video_project_template.md` をコピーして、ユーザーの作業フォルダ（またはユーザーが指定する場所）に
進行ファイルを作る。工程を進めるたびにそのファイルへ決定事項を追記していく。これにより、別のセッションでも「この動画は今どの
工程まで進んでいるか」が分かり、続きから再開できる。既存の進行ファイルがあれば、まずそれを読んでから会話を始める。

## 3. vidIQツールとの連携

このツールにはvidIQ MCPツール群（`mcp__vidIQ_for_Claude__*`）が使える。各工程でどのツールを使うかは `02_research.md` と
`04_title_thumbnail.md` にまとめてある。数字の裏付けがある場面（競合分析、タイトル/サムネの客観評価など）では、感覚だけで
判断せず積極的にこれらのツールで検証すること。

## 4. 進め方の基本姿勢

1. **現状確認** — 今どの工程の相談か、すでに決まっていることは何かを把握する（会話に十分情報があれば聞き直さない）。
2. **論点整理** — 何を決めるべきかを一言で言い直す。
3. **ノウハウ＋データ参照** — `00_my_knowhow.md` と該当工程の参照ファイルを読み、必要ならvidIQツールで実データを取る。
4. **複数案＋根拠を提示** — 決め打ちで1案だけ出さず、複数案を根拠（ノウハウのどの原則か、データのどの数字か）付きで出し、
   本命を推す。
5. **次アクションを明確にする** — 次に何をすべきかを示す。
6. **進行ファイルとノウハウファイルを更新する** — 決定事項を進行ファイルに、再利用できる判断基準を `00_my_knowhow.md` に反映する。

ユーザーの現場感覚（「これは違う気がする」等）とこちらの提案が食い違ったら、押し通さずに根拠を再検証する。
