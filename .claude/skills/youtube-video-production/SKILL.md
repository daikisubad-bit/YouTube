# YouTube動画制作ツール

ユーザー（daiki）が自分のチャンネルの動画を作るための、一気通貫の制作パイプライン。単発の一般論アドバイスではなく、`references/`
にある**統合ノウハウ（考え方）＋ユーザー自身のチャンネル固有ノウハウ**と、vidIQ MCPツールで取得した**実データ**の三つを根拠にして、
各工程の具体案を出す。

## 大前提

**数字は結果であって原因ではない。** 「効果があるから」で終わらせず、なぜ人間がその感情になるのか（本質）を理解した上で
企画・タイトル・サムネ・台本を作る。借り物の理論やジャンル共通のテンプレより、ユーザー自身の経験・実感に紐づいた案の方が
強い。詳細は `references/knowhow_master.md` 第1章。この姿勢は全工程を貫く前提として常に持っておくこと。

## 0. 最初にやること：ノウハウの有無を確認する

**毎回、まず以下の2つを読むこと。**

1. **`references/knowhow_master.md`** — 汎用の「考え方」の本体（リサーチ〜企画〜タイトル/サムネ〜台本〜CTA〜KPIまでの
   思考体系、失敗パターン32、レビュー質問集などを含む全18章）。ジャンル・チャンネルを問わず使える判断基準。
2. **`references/00_my_knowhow.md`** — ユーザー本人・このチャンネル固有のノウハウ（ターゲット、確定文言、過去の成功/失敗
   の実例など）が蓄積されていく場所。

両方に該当する内容があれば、**`00_my_knowhow.md`（チャンネル固有）を最優先**し、`knowhow_master.md`（汎用の考え方）で
補う。`01_foundation.md` 以降の各工程ファイルは、この2つを読んだ上で「今回どの章を見るか」の案内役とvidIQツールの
使い分けを担う短いガイド。

- `00_my_knowhow.md` の該当セクションがまだ空欄／TODOのままなら、`knowhow_master.md` の汎用フレームワークだけで進めずに、
  その場で必要な判断基準をユーザーに1〜2個だけ質問する（根掘り葉掘り聞きすぎない）。聞いた内容は会話の中で使うだけでなく、
  **`00_my_knowhow.md` の該当セクションに追記して**、次回以降は聞き直さずに済むようにする。
- こうして使うたびに `00_my_knowhow.md` が育っていく設計。ユーザーがまとまった資料やテキストを渡してきたときは、
  「チャンネル固有の実例・確定文言」なら `00_my_knowhow.md` に、「ジャンルを問わない考え方・原則」なら
  `knowhow_master.md` に、内容を見て振り分けて整理する。`knowhow_master.md` は汎用の考え方の本体なので、基本的には
  上書きせず、明確な追加・改訂がある場合のみユーザーと確認の上で更新する。

## 1. 全体フロー

```
0. チャンネル基盤（最初に1回。以後は土台として参照するだけ）
     ↓
1. リサーチ・ネタ出し   → references/02_research.md
     ↓
2. 企画                → references/03_planning.md
     ↓
3. タイトル・サムネ     → references/04_title_thumbnail.md
     ↓
4. 差別化ポイント       → references/05_differentiation.md
     ↓
5. 台本                → references/06_script.md
     ↓
6. 公開後フィードバック → references/07_feedback_loop.md（動画公開後、結果が出たら実施）
```

| 工程 | いつ使うか | 参照ファイル | `knowhow_master.md` 該当章 |
|------|-----------|-------------|-------------------------|
| 0. チャンネル基盤 | チャンネル・ペルソナ・世界観がまだ言語化されていないとき、または前提を確認したいとき | `references/01_foundation.md` | 第1章、第5章、第16章 |
| 1. リサーチ | ネタが欲しい、競合を調べたい、トレンドを知りたい | `references/02_research.md` | 第3章、第7章 |
| 2. 企画 | リサーチ結果から動画の切り口・構成を決めたい | `references/03_planning.md` | 第4章、第5章 |
| 3. タイトル・サムネ | タイトル案、サムネの文言・構図案が欲しい | `references/04_title_thumbnail.md` | 第6章、第11章 |
| 4. 差別化ポイント | 似た動画との違いを言語化したい | `references/05_differentiation.md` | 第4章（4-2, 4-4）、第16章（16-3） |
| 5. 台本 | 台本を書く／直したい | `references/06_script.md` | 第8〜10章、第11章、第12章 |
| 6. 公開後フィードバック | 動画を公開して数字が出た後、次に活かしたい | `references/07_feedback_loop.md` | 第14章 |

工程4（差別化ポイント）は独立ステップだが、実務上は工程2（企画）を決める瞬間に同時決着することが多い。企画を詰めるときは
`05_differentiation.md` のチェックも一緒に見ること。

複数の動画を並行して回す・進捗が滞る場面では `references/08_production_ops.md`（`knowhow_master.md` 第15章）も参照する。
これは特定の工程ではなく、全工程を横断する制作進行管理の考え方。

## 2. 動画ごとの進行管理

新しい動画の相談が始まったら、`templates/video_project_template.md` をコピーして `projects/<動画のスラッグ>.md`
として保存する。工程を進めるたびにそのファイルへ決定事項を追記していく。これにより、別のセッションでも「この動画は
今どの工程まで進んでいるか」が分かり、続きから再開できる。既存の進行ファイルがあれば、まずそれを読んでから会話を
始める。

## 2b. 制作ツール（`tool/index.html`）

`tool/index.html` は、5工程（リサーチ／企画／タイトル・サムネ／差別化ポイント／台本）それぞれの入力フォームを
まとめたページで、Artifactとして公開している。ユーザーはここでフォームに入力し、「コピーしてClaude Codeに
貼り付ける」ボタンで指示文をクリップボードにコピーして、このチャットに貼り付けて使う（ページ単体では生成できない
ため、貼り付けられて初めて実際の生成が動く）。

貼り付けられたテキストは「リサーチをお願いします。」「企画を考えてください。」「タイトルとサムネの案をお願いします。」
「差別化ポイントを言語化してください。」「台本を書いてください。」のいずれかで始まり、続けて `ラベル: 値` の形式で
入力内容が並ぶ。これを受け取ったら、通常のチャットでの依頼と同じように扱い、該当工程（`references/02_research.md`
〜`06_script.md`）のノウハウとvidIQツールを使って実際に案を作成して返す。並行して、対応する `projects/<スラッグ>.md`
があれば決定事項を追記し、なければ新規に作成する。

`tool/index.html` 自体の見た目やフォーム項目を変更したいと言われたら、他のArtifactと同様にファイルを編集して
同じファイルパスから再publishする（URLは維持される）。フォームはHTML内の `tools-data` というJSON（`id`, `title`,
`fields` など）で定義されているので、工程の追加・項目の変更はここを編集すればよい。

## 3. vidIQツールとの連携

このツールにはvidIQ MCPツール群（`mcp__vidIQ_for_Claude__*`）が使える。各工程でどのツールを使うかは `02_research.md` と
`04_title_thumbnail.md` にまとめてある。数字の裏付けがある場面（競合分析、タイトル/サムネの客観評価など）では、感覚だけで
判断せず積極的にこれらのツールで検証すること。

## 4. 進め方の基本姿勢

1. **現状確認** — 今どの工程の相談か、すでに決まっていることは何かを把握する（会話に十分情報があれば聞き直さない）。
2. **論点整理** — 何を決めるべきかを一言で言い直す。
3. **ノウハウ＋データ参照** — `00_my_knowhow.md`・`knowhow_master.md`・該当工程の参照ファイルを読み、必要ならvidIQツールで
   実データを取る。
4. **複数案＋根拠を提示** — 決め打ちで1案だけ出さず、複数案を根拠（ノウハウのどの原則か、データのどの数字か）付きで出し、
   本命を推す。
5. **仕上げ前にレビューする** — 企画・タイトル/サムネ・台本を確定する前に、`knowhow_master.md` 第17章（失敗パターン32・
   レビュー質問集）に該当項目がないか一度照らし合わせる。
6. **次アクションを明確にする** — 次に何をすべきかを示す。
7. **進行ファイルとノウハウファイルを更新する** — 決定事項を進行ファイルに、再利用できる判断基準を `00_my_knowhow.md` に反映する。

ユーザーの現場感覚（「これは違う気がする」等）とこちらの提案が食い違ったら、押し通さずに根拠を再検証する。
